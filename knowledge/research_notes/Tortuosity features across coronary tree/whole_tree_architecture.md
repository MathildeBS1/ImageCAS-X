# Whole-tree / multi-vessel architecture and sample-size implications

## Architectural approaches for feeding multiple vessels or a branching tree into a learned model

### Takeaway
The literature clusters into three families matching the question's (a)/(b)/(c) split, but almost none of it targets a small classifier consuming an ordered local geometric profile like Model 2. The closest matches are: shared-weight per-vessel/per-segment classifiers scored independently per named vessel (family a, weak form), attention-based fusion of a variable number of per-lesion embeddings into one patient-level vector (family a, strong form), GNNs that put bifurcations/segments as nodes and vessels as edges (family b), and shared-encoder-plus-branch-specific-decoder patterns from segmentation work on other vascular trees (family c, by analogy only, not from coronary outcome prediction).

### Cited Findings
- **Family (a), weak form - shared model, scored per vessel, not fused:** Segment-level CCTA stenosis/plaque stratification models apply one classifier (2D nnU-Net-based Stenosis/Vulnerable-Plaque Segmentation Models, and transfer-learning classifiers such as EfficientNet/ResNet/DenseNet/Inception-ResNet) identically to LAD, LCX and RCA segments, reporting accuracy separately per vessel (0.81 LAD, 0.80 LCX, 0.79 RCA) rather than fusing vessels into one patient-level score — [Interpretable and reproducible machine learning model for coronary calcification and segment-level stenoses stratification, BMC Medicine](https://link.springer.com/article/10.1186/s12916-025-04478-0); vessel morphology differences (LAD/LCX overlap and twist in 2D projections vs. RCA's simpler shape) are cited as the likely cause of the vessel-to-vessel accuracy gap — [Deep Learning-Based Segmentation of Coronary Arteries and Stenosis Detection in X-Ray Coronary Angiography, JACC: Advances](https://www.jacc.org/doi/10.1016/j.jacadv.2025.102360).
- **Family (a), strong form - per-lesion embeddings fused into one patient-level vector:** AngioGraphCAD builds a geometric graph per lesion, learns a lesion-level embedding from coronary geometry plus clinical data with its own lesion-level prediction objective, then fuses the (variable-count) set of lesion embeddings with a masked-attention mechanism into a single interpretable patient-level representation, explicitly designed to accommodate a variable number of lesions per patient — [Future cardiovascular events prediction from invasive coronary angiography: a graph representation learning perspective, ScienceDirect](https://www.sciencedirect.com/science/article/pii/S1361841526001489) / [PubMed](https://pubmed.ncbi.nlm.nih.gov/42061118/). Reported performance: lesion-level AUC 0.71 (FAME2 cohort) and 0.73 (FCL cohort); patient-level AUC 0.70 (FAME2).
- **Family (b) - GNNs with bifurcations as nodes, vessels as edges:** In cerebral vasculature work, the vascular network is represented as a graph whose nodes are bifurcation points or vessel endpoints and whose edges are the vessel segments between them, and a MeshGraphNets-style GNN is trained on this representation to output flow rate and pressure at every node as a fast surrogate for full fluid-dynamics simulation, built from MRA images of 35 patients (mostly with stenosis) — [Graph Neural Network for Cerebral Blood Flow Prediction With Clinical Datasets](https://pith.science/paper/2411.17971). A physics-informed GNN for microvascular flow uses the same node-as-bifurcation, edge-as-vessel construction — [Physics-Informed Learning of Microvascular Flow Models using Graph Neural Networks](https://arxiv.org/pdf/2512.10792). On the coronary side, GNN/graph-matching methods (GCN combining geometry and image intensity of adjacent segments; association-graph matching networks; multi-graph graph matching) are used for automatic extraction and anatomical *labeling* of the coronary tree, not for outcome prediction, but they demonstrate the same "segments as graph elements, weights shared across the whole tree via message passing" design — [Graph neural networks for automatic extraction and labeling of the coronary artery tree in CT angiography, PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC11095121/); [AGMN: Association Graph-based Graph Matching Network for Coronary Artery Semantic Labeling](https://arxiv.org/pdf/2301.04733); [Multi-graph Graph Matching for Coronary Artery Semantic Labeling, PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC12288628/).
- **Family (c), by analogy from a different vascular tree (segmentation, not outcome prediction):** Hepatic-vein/portal-vein segmentation work uses one shared encoder feeding two branch-specific decoders (one per vessel system) trained under a multi-task Dice-Focal loss, explicitly to let the model share low-level features while still specializing per vascular structure — [Hepatic and portal vein segmentation with dual-stream deep neural network, Medical Physics](https://aapm.onlinelibrary.wiley.com/doi/abs/10.1002/mp.17090) / [PubMed](https://pubmed.ncbi.nlm.nih.gov/38648676/); [VSNet: Vessel Structure-aware Network for hepatic and portal vein segmentation](https://www.sciencedirect.com/science/article/abs/pii/S1361841525000064). This is the shared-trunk/specialized-branch pattern the question asks about for LM→daughters, but found only in a segmentation context on a two-branch (not four-branch, not depth-recursive) tree — treat as structural analogy, not precedent for a clinical classifier.
- **Named per-vessel sequence model, structurally closest to Model 2 but per-vessel not per-patient:** DeepVessel FFR (DVFFR) extracts per-location lesion/proximal/distal features along a single reconstructed 3D vessel path with a multilevel fully-connected network, then feeds the ordered sequence into a bidirectional recursive neural network (BRNN) that integrates information from both proximal and distal parts of that one vessel to output a per-vessel FFR value; first clinical validation used 63 patients and 71 vessels (i.e., a handful of patients contributed 2 vessels) — [Estimation of FFR in coronary arteries with deep learning, arXiv](https://arxiv.org/pdf/2405.12224) (context found via search summaries of DVFFR validation literature; direct primary DVFFR paper not independently fetched in this pass — see Gaps).
- A title-only hit, not fetched in full: "Bi-VesTreeFormer: A bidirectional topology-aware transformer framework for coronary vFFR estimation" appears to be a transformer explicitly designed around coronary tree topology for FFR estimation — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0895611125000734). Its architecture details were not verified (see Gaps).

### Inferences
- No coronary study found combines all three ingredients the thesis needs simultaneously: (1) an ordered per-point local geometric profile, not a bulk feature vector or an image, (2) multiple named vessels (RCA/LAD/LCx/LM) explicitly, and (3) a single per-patient clinical label. The AngioGraphCAD attention-fusion pattern is the nearest architectural template for turning several vessel-level (there, lesion-level) representations into one patient-level prediction while tolerating a variable number of inputs, which matters because not every patient will have a clean LM segment or full length on every daughter vessel.
- The segment-level stenosis literature's practice of applying one shared classifier to every named vessel, then reporting per-vessel accuracy, is evidence that a single shared-weight model generalizes across RCA/LAD/LCx reasonably well (accuracies within ~2 points of each other) even without vessel-specific weights, at least for stenosis classification from image-derived segments.

### Gaps
- No study was found that uses a per-point ordered geometric/curvature vector (as opposed to bulk radiomic features, images, or point-cloud/mesh graphs) as the unit combined across vessels. This is the specific gap the constraints section asks to flag explicitly: there is no direct precedent for "multi-vessel ordered local geometric profile input to a small classifier."
- The primary DeepVessel FFR paper and the Bi-VesTreeFormer paper were not fetched in full text (PDF extraction failed / not attempted respectively); their exact fusion mechanism across the whole tree (as opposed to per-vessel output) is not confirmed here.
- No coronary paper was found that runs a direct ablation of "concatenate per-vessel embeddings" vs. "GNN over the branching structure" vs. "hierarchical trunk/daughter" on the same task and dataset, so relative accuracy of the three families for a shared task is unknown.

## Whole-tree or multi-vessel coronary DL studies for CAD/stenosis/plaque/FFR, and whether combining vessels helped

### Takeaway
Found studies split cleanly by outcome level: AngioGraphCAD is per-patient (multi-lesion fusion); DeepVessel FFR and the segment-level stenosis/plaque stratification studies are per-vessel or per-segment (one label per anatomical unit, scored independently, not fused into a patient score). None of the retrieved studies reports an ablation isolating whether combining vessels improved prediction over a single-vessel-only baseline.

### Cited Findings
- **Per-patient outcome, multi-vessel/multi-lesion input:** AngioGraphCAD predicts future cardiovascular events at the patient level from invasive coronary angiography by fusing a variable number of per-lesion graph embeddings via masked attention; patient-level AUC 0.70 on FAME2 vs. lesion-level AUC 0.71 (FAME2) / 0.73 (FCL) — [ScienceDirect](https://www.sciencedirect.com/science/article/pii/S1361841526001489). The paper is framed around geometry-aware representations as "a promising step" rather than reporting a clean single-vessel-only ablation number in the summarized text.
- **Per-vessel outcome:** DeepVessel FFR predicts a per-vessel FFR value from a sequence model along that vessel's centerline; its first clinical validation cohort was 63 patients / 71 vessels — [context from arXiv 2405.12224 discussion of DVFFR validation](https://arxiv.org/pdf/2405.12224).
- **Per-segment outcome, vessel identity as the unit of evaluation, not fusion target:** Segment-level plaque/stenosis stratification across LAD, LCX and RCA reports accuracy separately per named vessel (0.81/0.80/0.79) using one shared model architecture, i.e., "multi-vessel" here means "applied identically to each of several vessels and scored per-vessel," not "combined into one patient score" — [BMC Medicine](https://link.springer.com/article/10.1186/s12916-025-04478-0). A related JACC: Advances paper reports RCA generally has the highest detection rates and LAD/LCX are harder because they overlap and twist in 2D projections — [JACC: Advances](https://www.jacc.org/doi/10.1016/j.jacadv.2025.102360).
- **Mortality/CAD-risk GNN work is feature-graph, not vessel-anatomy-graph, based on what was retrievable:** the lightweight interpretable GNN for long-term CAD mortality prediction ("CAD-SS") is described as using "a concise set of critical features" for a causality-aware graph model; the retrieved abstract-level text does not establish that its graph nodes are anatomical vessels/segments rather than clinical/risk-factor variables — [ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S1532046425000759) / [PubMed](https://pubmed.ncbi.nlm.nih.gov/40360137/). Treat this as *not* confirmed as a multi-vessel anatomical-tree study (see Gaps).

### Inferences
- The one confirmed per-patient multi-vessel/multi-lesion coronary DL study found (AngioGraphCAD) treats "how many lesions/vessels contribute" as a variable-cardinality set-fusion problem (attention pooling over an unordered, variable-length set of lesion embeddings) rather than a fixed 3- or 4-slot concatenation of named vessels (RCA/LAD/LCx/LM). This suggests that if a fixed vessel-identity slot for LM is sometimes empty (short or absent left main), a fusion/pooling design that tolerates missing branches is more directly supported by precedent than a fixed-width concatenation architecture that assumes all four vessels are always present.

### Gaps
- No study was found that explicitly states "combining vessels improved prediction over single-vessel models" with a quantified before/after comparison; this specific comparison (the second half of key question 2) is unanswered by the retrieved literature.
- Whether the CAD-SS mortality GNN's graph nodes are anatomical (per-vessel/per-segment) or purely clinical/tabular features was not resolved from the retrieved abstract text; the primary paper was not fetched in full.

## Sample-size / overfitting arithmetic: does combining vessels per patient meaningfully increase independent training signal?

### Takeaway
The general clustered-data and repeated-measures statistics literature is unambiguous that treating multiple correlated observations from one subject as independent training/test instances inflates effective sample size and understates uncertainty; this is a general statistical result, not something found stated specifically for the multi-vessel-per-patient coronary case, so the application to Model 2's arithmetic is an inference, not a cited fact about this exact setup.

### Cited Findings
- In classical repeated-measures/clustered regression, if one analyzes clustered data with a model that assumes independence and ignores the clustering, the standard errors of patient-level (time-invariant) predictors are systematically underestimated — [Avoiding Blunders When Analyzing Correlated Data, Clustered Data, or Repeated Measures, Journal of Rheumatology](https://www.jrheum.org/content/50/10/1269).
- In nested experimental designs where multiple observations come from a single research subject (the paper's own example is multiple neurons from one animal, directly structurally analogous to multiple vessels from one patient), 53% of surveyed papers in the field used this kind of nested data, and ignoring the resulting non-independence when testing for group differences can push the true false-positive rate up to about 80% against a nominal 5% alpha — [Aarts et al., "effective sample size" analysis of nested designs (PDF)](https://web.math.princeton.edu/~sswang/literature_general_unsorted/aarts_effective_sample_size_NN.pdf).
- In neuroimaging specifically, when multiple measurements originate from the same individuals across multiple brain regions, the regions share physiological/anatomical correlation, and treating them as independent artificially inflates effective degrees of freedom, which understates standard error and increases false-positive risk; a subject-level bootstrap (resampling whole subjects, not individual region-measurements) is recommended to respect this dependency structure — search-aggregated summary of neuroimaging sample-size / effect-size literature (exact primary source not individually resolved from the aggregated result; see Gaps for citation caveat). A dedicated methodological reference on quantifying and reporting this kind of clustering is [Beyond Point Estimates: Toward Proper Statistical Inferencing and Reporting of Intraclass Correlation Coefficients, arXiv](https://arxiv.org/pdf/2601.02765).
- Overfitting risk rises specifically because "the number of random effects needed to represent all the clusters may be considerable," and the recommended mitigations are either penalized/shrinkage methods (e.g., lasso-style regularization) or simplifying the assumed covariance structure to reduce the number of estimated parameters — [Clustered data with small sample sizes: comparing model-based and design-based approaches](https://www.tandfonline.com/doi/full/10.1080/03610918.2014.983648).
- In the closest deep-learning analogue found — multi-lead ECG modeling, where one patient contributes 12 correlated leads recorded simultaneously — the field's standard response is architectural (multi-channel input, lead-asymmetric pooling, independent feature branches feeding one shared classifier) rather than treating each lead as an additional independent training case; separately, ECG deep learning papers explicitly flag that if multiple ECG recordings from the same patient appear in both train and validation/test splits, the model can learn patient-specific signal rather than disease-specific signal, inflating apparent performance, and the standard fix is strict patient-level (not recording-level) data splitting — [Deep Learning Applied to 12-Lead ECGs for Detection of Structural, Metabolic and Systemic Disease](https://www.mdpi.com/2075-4418/16/17/2834); leakage-control discussion in [Wolff-Parkinson-White Detection at 471:1 Class Imbalance: A Leakage-Controlled Study of the Data Bottleneck, arXiv](https://arxiv.org/pdf/2608.14633).

### Inferences
- By direct structural analogy to the nested-design and multi-lead-ECG literature: if RCA/LAD/LCx(/LM) per-patient vessel profiles are treated as 3-4 separate training *instances* rather than as 3-4 *channels* of one instance, the model's effective sample size for generalization purposes is closer to the number of patients than to the number of (patient x vessel) pairs, because the four vessels within a patient share the patient's age, sex, systemic disease burden, and CAD label; the "extra" instances are correlated draws, not independent ones. The correct statistical treatment mirrors the clustered-data literature's recommendations: evaluate with patient-level (not vessel-level) cross-validation splits, and if vessel-level training instances are used, account for the clustering (e.g., cluster-robust variance estimation analogues, or a subject-level bootstrap for reporting uncertainty) rather than reporting per-vessel n as if each were IID.
- This means a naive "4 vessels x 200 patients = 800 training instances" framing overstates the effective sample size for a small classifier's overfitting risk; the honest accounting is still closer to 200 independent patients, with the multi-vessel data functioning more like additional correlated features/channels per patient (as in the ECG lead analogy) than like additional independent labeled examples.

### Gaps
- No paper was found addressing this exact scenario (multiple correlated vessel-level geometric profiles per patient, single patient-level clinical label, small neural network) directly; every finding above is drawn from adjacent domains (general clustered-data statistics, neuroimaging nested designs, multi-lead ECG) and applied by analogy, per the instructions to flag this explicitly.
- The specific neuroimaging "subject-level bootstrap" claim came from an aggregated search summary rather than a single traceable primary source; treat that specific sentence as lower-confidence until traced to a primary citation.
- No quantitative guidance was found on exactly how much shrinkage of effective sample size to assume for a given intra-patient correlation strength (e.g., an explicit design-effect formula applied to a vessel-tree scenario); the intraclass-correlation/design-effect logic is well established for clustered survey/trial data in general but was not found instantiated numerically for coronary vessel geometry.

## Vessel-specific models vs. one shared-weight model across named vessels or tree branches

### Takeaway
No study was found running a direct, controlled ablation of "separate network per named vessel" vs. "single shared-weight network across all vessels" on the same coronary task. The indirect evidence that exists (shared models applied per-vessel in coronary imaging, and shared-encoder/branch-specific-decoder or position-aware designs in airway and hepatic vein trees) leans toward shared-weight-plus-branch/position-identity as the more common design choice, but this is inferred from convention rather than from a head-to-head comparison.

### Cited Findings
- **Coronary (indirect):** Multiple segment-level stenosis/plaque studies apply one shared classifier architecture identically to LAD, LCX and RCA and report per-vessel accuracy separately (0.81/0.80/0.79), rather than training three separate per-vessel networks — [BMC Medicine](https://link.springer.com/article/10.1186/s12916-025-04478-0). The residual accuracy gap between vessels is attributed to vessel-specific morphology/imaging difficulty (LAD/LCX overlap and twist vs. RCA's simpler shape), not to the model lacking vessel-specific weights — [JACC: Advances](https://www.jacc.org/doi/10.1016/j.jacadv.2025.102360). This is evidence that a shared model works reasonably across named coronary vessels, but it is not evidence about how a vessel-specific alternative would have performed, since no such comparison arm was reported in what was retrieved.
- **Airway trees:** BranchLabelNet explicitly rejects a single undifferentiated shared model in favor of a "divide-and-group" multi-label design that accounts for the fractal, highly variable branching structure of the airway tree, and separately applies class weights that treat target branches (trachea, two main bronchi, segmental branches) differently from the rest (weights 0.8 vs. 0.2) — [BranchLabelNet, PubMed](https://pubmed.ncbi.nlm.nih.gov/38777935/). A structure-and-position-aware GNN for airway labeling instead keeps one shared GNN but explicitly encodes each branch's position/structure within the tree as an input feature, rather than instantiating a separate network per named branch — [Structure and position-aware graph neural network for airway labeling, ScienceDirect](https://www.sciencedirect.com/science/article/pii/S1361841524002111). BCNet trains a Point-Voxel GNN branch and a CNN voxel-labeling branch jointly on a shared backbone to learn topology-aware features, again a shared-weight-with-topology-input design rather than per-branch networks — [BCNet, arXiv](https://arxiv.org/html/2205.06947).
- **Hepatic/portal vein trees (segmentation, not classification):** the standard design is one shared encoder plus separate, vessel-system-specific decoders (hepatic vein decoder, portal vein decoder), explicitly to let the network share generic vascular features while specializing per vessel system — [Medical Physics](https://aapm.onlinelibrary.wiley.com/doi/abs/10.1002/mp.17090); [VSNet](https://www.sciencedirect.com/science/article/abs/pii/S1361841525000064). This is a two-branch case, not a four-branch, depth-recursive one, and it is a segmentation task, not an outcome classifier, so it only weakly generalizes to the LM-trunk/RCA-LAD-LCx-daughter classification question.
- **Cerebral vasculature:** GNN blood-flow surrogates (MeshGraphNets-style) apply the same shared message-passing weights to every node/edge in the vascular graph regardless of which named vessel or bifurcation it belongs to, relying on local graph structure and physical state rather than a vessel-identity label or per-vessel sub-network — [Graph Neural Network for Cerebral Blood Flow Prediction](https://pith.science/paper/2411.17971).

### Inferences
- Across every tree type examined (coronary, airway, hepatic/portal, cerebral), the more common pattern in the retrieved literature is a shared-weight backbone with some form of branch- or position-identity signal injected as an input or as a lightweight task-specific head, rather than fully independent per-vessel networks trained from scratch. This favors, for Model 2's extension, a design where vessel identity (RCA/LAD/LCx/LM) is passed in as a categorical input or used to select a small vessel-specific head on top of a shared trunk, over training four entirely separate small networks, both because it uses the pooled cross-vessel data more efficiently for a small network and because it matches the convention seen elsewhere.
- No evidence was found either way on whether such shared-weight-plus-identity designs actually outperform fully separate per-vessel networks in a small-sample regime specifically; the inference above is about architectural convention, not about proven superior accuracy.

### Gaps
- No head-to-head coronary, airway, cerebral, or hepatic study was found that trains and compares (i) fully separate per-vessel/per-branch networks against (ii) one shared network with a vessel/branch-identity input, on the same dataset and task. This is a direct gap against the fourth key question as posed.
- No study was found addressing this comparison specifically for a small network (few parameters, small training set) as opposed to the large segmentation/GNN backbones surveyed here; whether the shared-vs-specific tradeoff changes direction at small model/data scale is unknown from this search.
