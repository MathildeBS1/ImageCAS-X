\section{Training}
\label{sec:pipeline-training}

Training adjusts the network's weights so its prediction increasingly agrees with the GT mask.
That requires a \textbf{loss}, one number scoring how wrong a prediction is, and an
\textbf{optimizer}, a rule for turning that number into a weight update.

Plain pixel accuracy is close to useless in our case: a coronary artery occupies well under one percent
of a volume, so predicting ``background'' everywhere already scores above 99\,\%. The
\textbf{Sørensen--Dice coefficient} instead measures overlap relative to the size of the two
regions being compared:
\begin{equation}
  \mathrm{Dice}(P, G) = \frac{2\,|P \cap G|}{|P| + |G|} \in [0, 1],
  \label{eq:pipeline-dice}
\end{equation}
for a predicted region $P$ and GT region $G$. An empty prediction scores 0, not 99\,\%. This form
is not differentiable: $|P|$, $|G|$ and $|P \cap G|$ are counts over a thresholded, all-or-nothing
prediction, and thresholding has zero gradient almost everywhere, so it gives the optimizer no
direction to push any weight (see backpropagation, below).
CAS-Net instead trains on V-Net's soft Dice loss \cite{milletari2016vnet}: it replaces the hard,
thresholded counts with the network's raw softmax probabilities, so the loss becomes a smooth
function of the weights that a gradient can actually flow through, averaged over its two output
channels (background, lumen):
\begin{equation}
  \mathcal{L}_{\mathrm{Dice}} = \frac{1}{C}\sum_{c=1}^{C}\left(1 -
    \frac{2\sum_i p_{c,i}\,g_{c,i} + \epsilon}{\sum_i p_{c,i}^2 + \sum_i g_{c,i}^2 + \epsilon}\right),
  \qquad C = 2,\ \epsilon = 1,
  \label{eq:pipeline-soft-dice}
\end{equation}
Here $p_{c,i}$ is how confident the network is that voxel $i$ belongs to class $c$, and $g_{c,i}$
is 1 if it really does and 0 if it does not. The only real change from Equation~\ref{eq:pipeline-dice}
is that the denominator squares these values instead of just adding them up; that one change is
what turns the plain Sørensen--Dice formula into V-Net's own version of it.

The loss score on its own does not say how to change any individual weight. \textbf{Backpropagation}
works this out by passing the loss backward through the network and computing, for every weight, its
\emph{gradient}: which way, and by how much, that weight should move to make the loss a little
smaller. The \textbf{Adam} optimizer \cite{kingma2015adam} then uses these gradients to actually
update the weights. Rather than moving every weight by the same fixed step, it gives each weight
its own step size based on its recent gradient history, starting from a base learning rate of
$10^{-4}$ (weight decay $10^{-8}$) that shrinks smoothly toward zero as training goes on, so the
network takes big steps early and finer, more careful ones later:$
  \mathrm{lr}(e) = 10^{-4}\left(1 - e/E\right)^{0.9}, \qquad E = 1000.$


Figure~\ref{fig:pipeline-training-loop} walks through one epoch start to finish: a fixed batch of
training iterations, then a validation pass that does not update any weights, then the two
checkpoints that validation result decides between.

\subsection{Data augmentation}
\label{sec:pipeline-augmentation}
The training split holds 560 scans, all acquired with the same imaging protocol. \textbf{Data
augmentation} helps the network avoid overfitting to that particular protocol's noise level,
contrast timing and slice thickness, without collecting extra scans. This matters beyond the
ImageCAS test split: these weights will later be applied to the Copenhagen General Population
Study (CGPS, ``Herlev--{\O}sterbro''), whose participants were almost certainly
scanned under a different protocol, with no further fine-tuning planned before that happens. The
robustness this augmentation buys is what that transfer depends on.

  \begin{itemize}
    \item \textbf{Flip}: mirrors left--right and anterior--posterior, never the
      craniocaudal (head-to-foot) axis, since that would reverse a vessel's taper direction.
    \item \textbf{Gaussian noise}: simulates a noisier acquisition.
    \item \textbf{Gaussian blur}: simulates a coarser reconstruction kernel or motion blur.
    \item \textbf{Multiplicative brightness}: simulates a different contrast-bolus dose or timing.
    \item \textbf{Contrast}: stretches or compresses values around the crop's own mean, simulating
      different scanner contrast settings.
    \item \textbf{Simulated low resolution}: a downsample-then-upsample round trip, simulating a
      thicker slice spacing than the resampled resolution every scan shares
      (Section~\ref{sec:pipeline-data}).
    \item \textbf{Gamma remapping}: non-linearly redistributes intensity while holding the crop's
      mean and spread fixed, simulating different display windowing.
  \end{itemize}
